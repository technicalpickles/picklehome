# CLAUDE.md — picklehome

## Network Topology

```
Client → USG (192.168.1.1) → AT&T BGW (192.168.8.254) → AT&T Fiber → Internet
```

- **LAN:** `192.168.1.x`, gateway USG at `192.168.1.1`
- **AT&T BGW (fiber gateway):** `192.168.8.254` — admin UI at `http://192.168.8.254`
- **ISP:** AT&T Fiber, AS7018, southeastern US (Atlanta area)
- **Double-NAT:** BGW is NOT in IP passthrough mode; USG gets a private WAN IP

## Secrets & Config

Secrets are stored in 1Password and injected into `.env` via `op inject`. Most secrets live in the **picklehome** vault; a few may reference other vaults (e.g. `Personal`).

- `.env.template` — checked in, documents required secrets as `{{ op://vault/item/field }}` references
- `.env` — gitignored, plaintext, generated by `just dotenv`

**Setup on a new machine:** sign into 1Password (`op signin`), then run `just dotenv`.

**Adding a new secret:**
1. Add the value to 1Password (prefer the `picklehome` vault)
2. Look up the exact field name: `op item get "Item Name" --vault picklehome --format json | jq '[.fields[] | {label, id}]'`
3. Add the `{{ op://picklehome/Item/field }}` reference to `.env.template`
4. Run `just dotenv` to regenerate `.env`

**If `just dotenv` fails with missing keys:** keys present in the old `.env` are absent from the template — add them to `.env.template` then re-run. To skip the check and reset from the template unconditionally, use `just dotenv --force`.

**If `just dotenv` fails with a 1Password error:** ensure you're signed in (`op whoami`). Field names in `op://` references must match exactly — use the `jq` command above to verify.

The logic lives in `scripts/dotenv` (supports `--template`, `--output`, `--force`).

Scripts load `.env` automatically via `python-dotenv` (or `just`'s `set dotenv-load`).
