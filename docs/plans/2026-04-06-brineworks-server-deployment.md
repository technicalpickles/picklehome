# Brineworks Server Deployment

Deploy the brineworks PRM (Personal Relationship Manager) server to picklelab.

## What is brineworks-server?

A FastAPI REST API for managing personal contacts, interactions, relationships, and organizations. It's the backend for the brineworks email triage pipeline: emails get triaged, contacts get extracted, and sync-prm pushes them into this server.

**Source repo:** `technicalpickles/brineworks` (private), under `server/`.

**Stack:**
- Python 3.11, FastAPI 0.115+, Uvicorn
- PostgreSQL 16 (async via asyncpg + SQLAlchemy 2.0)
- Alembic for migrations
- Pydantic Settings for config

## Source repo structure (`server/` directory)

```
server/
  Dockerfile                    # python:3.11-slim, pip install, copies app + alembic
  docker-compose.yml            # postgres:16-alpine + server service
  docker-compose.override.yml   # dev: exposes postgres 5432, disables server container
  pyproject.toml                # deps: fastapi, uvicorn, sqlalchemy, asyncpg, alembic, pydantic-settings
  alembic.ini                   # migration config (script_location = alembic/)
  .env.example                  # BRINEWORKS_DATABASE_URL, BRINEWORKS_ECHO_SQL
  .env.db.example               # POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
  brineworks_server/
    app.py                      # FastAPI app factory, /health endpoint
    config.py                   # Pydantic Settings, env prefix BRINEWORKS_
    db.py                       # async engine + session factory
    models/                     # SQLAlchemy ORM (contacts, interactions, orgs, etc.)
    routers/                    # 8 API routers (contacts, interactions, relationships, ...)
    schemas/                    # Pydantic request/response models
    services/                   # business logic (promote, archive, triage queue)
  alembic/
    env.py                      # async migration runner
    versions/
      0001_initial_prm_schema.py  # full schema: contacts, interactions, orgs, etc.
```

## Dockerfile

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY pyproject.toml .
RUN pip install --no-cache-dir .
COPY brineworks_server/ brineworks_server/
COPY alembic/ alembic/
COPY alembic.ini .
CMD ["sh", "-c", "alembic upgrade head && uvicorn brineworks_server.app:app --host 0.0.0.0 --port 8000"]
```

Runs migrations on every startup, then starts uvicorn on port 8000.

## Environment variables

**App (.env):**

| Variable | Required | Description |
|----------|----------|-------------|
| `BRINEWORKS_DATABASE_URL` | yes | Async postgres URL, e.g. `postgresql+asyncpg://user:pass@db:5432/brineworks` |
| `BRINEWORKS_API_KEY` | yes | Bearer token for API authentication (all endpoints except /health) |
| `BRINEWORKS_ECHO_SQL` | no | Log SQL queries (default: false) |

Config uses Pydantic Settings with `env_prefix = "BRINEWORKS_"` and reads from `.env` file.

**Database (.env.db):**

| Variable | Required | Description |
|----------|----------|-------------|
| `POSTGRES_USER` | yes | Database user |
| `POSTGRES_PASSWORD` | yes | Database password |
| `POSTGRES_DB` | yes | Database name |

## API endpoints

- `GET /health`: returns `{"status": "ok"}` if DB is reachable, 503 otherwise
- `GET /docs`: Swagger UI (auto-generated by FastAPI)
- 8 resource routers: `/contacts`, `/contact_info`, `/interactions`, `/relationships`, `/organizations`, `/contexts`, `/locations`, `/links`
- Special: `POST /contacts/get-or-create-by-info`, `POST /contacts/{id}/promote`, `POST /contacts/{id}/archive`, `GET /contacts/triage`

## Deployment approach

**Build from source on picklelab.** The brineworks repo is private, so we clone it to the host and docker compose builds from the local checkout. No published container image.

### Repo on picklelab

Clone `brineworks` to a known location on the host. The compose build context points there.

### Service structure (following picklehome conventions)

```
homelab/services/brineworks-server/
  compose.yaml                   # base: postgres + server (build context refs local clone)
  compose.picklelab.yaml         # host: loopback port, /srv/data volume mounts
  deploy.sh                      # idempotent: clone/pull repo, create dirs, tailscale serve, systemd
  brineworks-server.service      # systemd unit
  .env.vars                      # BRINEWORKS_DATABASE_URL, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
  README.md                      # setup and ops docs
```

### Secrets (1Password)

Create a `Brineworks Server` item in the `picklehome` 1Password vault:

| Field | How to generate |
|-------|-----------------|
| `db_password` | `openssl rand -base64 32` |
| `api_key` | `openssl rand -hex 32` |

The database URL is derived: `postgresql+asyncpg://brineworks:<db_password>@db:5432/brineworks`.

### Networking

- Server binds to `127.0.0.1:8000` on picklelab (loopback only)
- Tailscale serve proxies `https://brineworks.<tailnet>.ts.net` to `127.0.0.1:8000`
- Requires defining a `brineworks` Service in Tailscale admin (same as vikunja pattern)

### Data locations on picklelab

```
/srv/data/brineworks-server/db/     # Postgres data directory
/srv/data/brineworks-server/dumps/  # pg_dumpall for backups (future)
```

### Client config

The brineworks CLI (`bw email sync-prm`) uses `BRINEWORKS_PRM_URL` to target the server. Currently defaults to `http://127.0.0.1:8000` for local dev. The CLI loads env vars from `.env` via python-dotenv. After deployment, set in the brineworks repo `.env`:

```
BRINEWORKS_PRM_URL=https://brineworks.<tailnet>.ts.net
BRINEWORKS_API_KEY=<same key as server>
```
