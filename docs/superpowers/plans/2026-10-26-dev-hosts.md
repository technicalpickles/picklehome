# picklehome dev hosts implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an OrbStack machine that every `just deploy-<service>` recipe targets unmodified, cloned from a golden machine, with picklelab's deploy path provably unchanged.

**Architecture:** host identity moves from literals in `deploy.sh` into a per-host env file read by one sourced helper. `scripts/service-env` gains a per-host overlay so one `.env.template` serves every host. A `deploy-preflight` script owns the Mac-side guards for both deploy recipes. Golden, new, rm and ls are shell scripts under `homelab/devhost/` with `just` wrappers.

**Tech Stack:** bash, just, OrbStack `orb` CLI, 1Password `op`, Tailscale, pytest with stub executables on `PATH` (the pattern in `tests/homelab/test_wait_for_health.py`).

**Spec:** `docs/plans/2026-10-26-dev-hosts.md`. Its "Refinements from planning" section records four small changes this plan makes to it.

## Global constraints

- picklelab's behavior is unchanged. Proof is `homelab/scripts/host-snapshot.sh` output before and after, with an empty diff (Task 1, Task 2, Task 6).
- Every `deploy.sh` that reads a `HOMELAB_*` variable sources `homelab/scripts/host-identity.sh` right after `deploy-lock.sh`, and references the variables as `${VAR?}` so a script that forgot to source fails instead of serving a prod name from a dev box.
- Dev hosts are OrbStack machines with `isolated`, `isolate_network` and `forward_ssh_agent` all `true` and no `mounts`.
- Prod identity files are committed under `homelab/hosts/`. Dev identity files are generated under `homelab/hosts/local/`, which is gitignored, and copied to `/etc/opt/homelab/host.env` on the box.
- The two token file paths `/etc/opt/homelab/op-token-picklehome` and `/etc/opt/homelab/op-token-pickleclaw` stay. On a dev host both hold the dev service-account token.
- No em dashes, no `op:` scheme spelled out in comments (`op inject` parses comments).
- Commit after every task with a message file and `git commit -F`, scoped to the task's paths.

## Review focus

1. A host whose `hostname -s` has no identity file anywhere must fail the deploy with exit 78 naming both paths it looked at, never default to prod. Pinned by `test_missing_identity_exits_78` in Task 1.
2. A `deploy.sh` that reads `HOMELAB_SERVICE_SUFFIX` without sourcing the helper must fail under `set -u`, not serve `svc:openclaw` from a dev box. Pinned by `test_every_deploy_sh_that_uses_identity_sources_it` in Task 1.
3. `just deploy-openclaw host=picklelab.tail2023b7.ts.net` must get prod rules through the alias list, and an unknown host must be refused, not treated as dev. Pinned by `test_alias_resolves_to_prod` and `test_unknown_host_refused` in Task 5.
4. An overlay key that is in neither the base template nor the service's `.env.vars` is a typo and must warn on stderr. Pinned by `test_overlay_unknown_key_warns` in Task 2.
5. `devhost-new picklelab`, `devhost-new picklelab-golden`, and a name that already exists must refuse before `orb clone` runs. Pinned by `test_new_refuses_protected_and_existing_names` in Task 4.

Always refuses a dirty tree. `prod`: branch must be `main`; pushes when `HEAD != origin/main`. `dev`: pushes `HEAD:refs/heads/<branch>` and returns the branch. `HOMELAB_REPO_DIR` env points the lookup at a repo other than the cwd for tests.
- The recipes replace their inline guards with `eval "$(scripts/deploy-preflight {{host}})"` and replace `git pull` on the host with `git fetch -q origin "$DEPLOY_REF" && git checkout -q -B "$DEPLOY_REF" "origin/$DEPLOY_REF"`.
